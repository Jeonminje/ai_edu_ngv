# 코딩 및 검증 규칙, 구현 경계, 추적성 (템플릿 11~14장)

## 코딩 및 검증 규칙 (템플릿 11장)

- **코딩 표준**: 사용 언어의 코딩 표준(예: MISRA C/C++, 사내 코딩 가이드 등 프로젝트가 채택한 표준)을 명시하고, `module-decomposition.md`의 ISO 26262-6 Table 4 원칙(포인터 제한, 재귀 제한, goto 금지 등)이 코딩 표준에 반영되어 있는지 확인합니다. 프로젝트가 채택한 표준을 알 수 없으면 사용자에게 확인을 요청합니다 — 임의로 특정 표준을 확정하지 않습니다.
- **정적분석**: 적용할 정적분석 도구/규칙 세트와 위반 시 처리 기준(빌드 실패 여부 등)을 기록합니다.
- **단위검증 커버리지 기준 (ISO 26262-6)**: ASIL 등급에 따라 요구되는 구조적 커버리지 수준이 다름을 공개적으로 알려진 원칙에 따라 안내합니다 — 등급이 높을수록 구문 커버리지(Statement)에서 분기 커버리지(Branch), MC/DC(Modified Condition/Decision Coverage)까지 요구 수준이 강화되는 경향이 있습니다. 정확한 목표 수준/면제 근거는 프로젝트 안전 계획에서 확정된 값을 사용하고, 없으면 TBD로 표시합니다. 세부 시험 설계는 `SWE.4` 단위시험(`TPL-SWE4-001`)에서 다룹니다.
- **리뷰 기준**: 코드 리뷰 체크리스트 항목(계약 준수, 방어적 설계 원칙 준수, 코딩 표준 준수)을 명시합니다.

## 단위와 요구사항 할당 (템플릿 12장)

- 구현 단위 ↔ 아키텍처 요소 ↔ SW 요구사항 ↔ (예정) 단위시험 케이스 간 할당을 표로 정리합니다.
- 요구사항이 할당되지 않은 구현 단위, 반대로 어떤 단위에도 할당되지 않은 요구사항을 모두 갭으로 보고합니다.

## 구현 경계 (템플릿 13장)

- 생성 코드(코드 생성기 산출물), 외부 라이브러리/오픈소스, 플랫폼 종속 코드, 이번 설계에서 다루지 않는 범위를 명시적으로 구분합니다.
- 외부 라이브러리(오픈소스 포함)를 사용하는 경우 `WP_Templates/Engineering/SoftwareDetailedDesignAndUnitConstruction/TPL-SBOM-001_Python 의존성 SBOM FOSS 라이선스 목록 템플릿.xlsx`와 연계해 SBOM/라이선스 목록을 관리하도록 사용자에게 안내합니다.

## 추적성 (템플릿 14장)

- 아키텍처 요소 ↔ 상세설계 요소(모듈/함수) ↔ 소스 파일 ↔ 단위시험 케이스의 양방향 추적을 유지합니다.
- `TPL-TRC-001_양방향 요구사항 추적 매트릭스 템플릿.xlsx`와 동일한 원칙(끊긴 추적 없음, 고아 요소 없음)을 적용합니다.
