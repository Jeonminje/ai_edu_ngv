# 아키텍처 설계 원칙 (A-SPICE SWE.2 + ISO 26262-6)

이 참조는 A-SPICE 4.1 SWE.2(소프트웨어 아키텍처 설계)의 Base Practice와 ISO 26262-6(소프트웨어 개발) Table 3/4에서 공개적으로 알려진 소프트웨어 아키텍처 설계 원칙을 재구성한 것입니다.

## A-SPICE SWE.2 Base Practice — 설계서에 반드시 반영

| BP | 반드시 반영할 산출물 |
|---|---|
| 아키텍처 설계 (SW 구성요소, 인터페이스) | 논리 아키텍처, 컴포넌트 목록, 인터페이스 명세 |
| 요구사항의 아키텍처 요소 배분 | 요구사항 ↔ 아키텍처 요소 할당표 (누락/중복 없음) |
| 인터페이스 정의 | 내부/외부 인터페이스 명세 (ID, 제공자, 사용자, 데이터, 조건) |
| 동적 동작 기술 | 주요 시나리오의 시퀀스/상태 다이어그램 |
| 자원 사용(메모리/타이밍 등) 고려 | 자원 및 배포 경계 분석 |
| 대안 평가 | 최소 2개 이상의 아키텍처 구조 후보를 비교하고 선정 근거를 기록 — 이 프로젝트에서는 **사용자가 최종 선정** |
| 일관성/추적성 확립 | 요구사항 ↔ 아키텍처 ↔ (향후) 상세설계/통합시험 추적 매트릭스 |

`aspice-auditor` 스킬의 SWE.2 체크리스트로 산출물 자체의 CL2 충족 여부를 별도 감사할 수 있습니다. 이 스킬은 "아키텍처를 어떻게 설계할 것인가"에 집중합니다.

## ISO 26262-6 소프트웨어 아키텍처 설계 원칙

ISO 26262-6에서 공개적으로 알려진 원칙을 요약하면 다음과 같습니다. 안전 관련 소프트웨어(ASIL이 부여된 기능)를 포함하는 아키텍처에는 특히 아래를 예외 없이 적용합니다.

1. **모듈화 (Modularity)**: 하나의 소프트웨어 유닛/컴포넌트는 하나의 명확한 책임을 가져야 하며, 크기와 복잡도가 제한되어야 한다.
2. **캡슐화 (Encapsulation)**: 컴포넌트 내부 데이터/구현은 숨기고, 외부에는 정의된 인터페이스만 노출한다.
3. **적절한 추상화 수준의 계층화 (Hierarchical structure, appropriate level of granularity)**: 아키텍처는 이해 가능한 계층/레이어로 구성되어야 하며, 한 레벨에 너무 많은 요소가 몰리지 않아야 한다.
4. **낮은 결합도 / 높은 응집도 (Restricted coupling, high cohesion)** — 이 프로젝트의 **필수 준수 사항**. 상세 기준은 `solid-and-coupling-cohesion.md` 참조.
5. **복잡한 프로그래밍 구조 회피**: 재귀, 동적 메모리 할당, 포인터 산술, 멀티스레드 암묵적 공유 상태 등 ASIL이 높을수록 회피하거나 정당화 근거를 명시해야 하는 메커니즘을 식별하고 문서화한다.
6. **오류 검출/처리 메커니즘**: 오류 감지 위치, 전파 차단(오류 격리), 안전 상태(Safe State) 정의를 아키텍처 수준에서 명시한다 (템플릿 9장 "오류 격리와 안전 동작").
7. **정적/동적 분석 대상이 되는 표기법 사용**: 아키텍처를 다이어그램(UML/SysML 등)으로 표현해 정적 의존성과 동적 시나리오를 모두 검증 가능하게 한다.
8. **ASIL 분해/독립성**: 서로 다른 ASIL이 섞인 요소 간에는 충분한 독립성(간섭 없음)을 아키텍처 수준에서 논증하거나, 독립성이 없으면 전체를 더 높은 ASIL로 취급해야 한다. 정보가 없으면 임의로 판단하지 말고 사용자에게 ASIL 배분표를 요청한다.

## 변경 유연성 (Modifiability)

"변경에 유연하게 대처"하는 아키텍처를 위해 설계 시 다음을 항상 점검합니다:

- 요구사항 변경이 예상되는 영역(가변점, variation point)을 사전에 식별했는가?
- 가변점은 별도 컴포넌트/인터페이스로 격리되어, 변경이 다른 컴포넌트로 전파되지 않는가?
- 구현 기술(DB, 통신 프로토콜, 하드웨어 플랫폼 등) 교체 시 영향받는 컴포넌트가 최소화되는가? (포트-어댑터 스타일 등으로 외부 의존성을 경계에 격리했는가)
- 새로운 기능 추가 시 기존 컴포넌트를 수정하지 않고 확장으로 대응 가능한가 (OCP, `solid-and-coupling-cohesion.md` 참조)?

이 점검 결과는 템플릿 10장 "품질속성 분석"에 유지보수성/변경용이성 시나리오로 기록합니다.
