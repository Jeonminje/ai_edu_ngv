# 요구사항 품질 특성 (ISO/IEC/IEEE 29148 기반)

요구사항 품질은 **개별 요구사항 수준**과 **요구사항 집합(명세서 전체) 수준**으로 나누어 점검해야 합니다. 개별 문장이 완벽해도 집합으로서 모순되거나 빠진 부분이 있을 수 있습니다.

## 개별 요구사항 품질 특성

| 특성 | 의미 | 흔한 위반 예시 | 점검 방법 |
|---|---|---|---|
| **명확함 (Unambiguous)** | 하나의 해석만 가능해야 한다 | "시스템은 빠르게 응답해야 한다" (빠름의 기준 없음) | 정량적 기준·용어 정의가 있는지 확인 |
| **검증 가능함 (Verifiable)** | 테스트/검사/분석/시연 중 하나로 충족 여부를 확인할 수 있어야 한다 | "사용성이 좋아야 한다" | 이 요구사항을 검증할 구체적 테스트 케이스를 즉시 떠올릴 수 있는가 |
| **단일함 (Singular/Atomic)** | 하나의 요구사항은 하나의 기능/제약만 다뤄야 한다 | "시스템은 로그인 후 대시보드를 표시하고 5초 내 응답해야 한다" (기능+성능 혼재) | "그리고", "또한"으로 두 개 이상 요구가 묶여 있는지 확인 |
| **완전함 (Complete, 문장 단위)** | 필요한 정보(조건, 대상, 동작, 기준)가 문장 내에 모두 있어야 한다 | "에러 발생 시 처리한다" (어떤 처리인지 없음) | 주어-조건-동작-기준이 다 있는지 확인 |
| **실현 가능함 (Feasible)** | 현재 기술/예산/일정 내에서 구현 가능해야 한다 | 검증되지 않은 기술에 의존하는 요구 | 설계/아키텍처 팀 검토 여부 확인 |
| **필요함 (Necessary)** | 이해관계자 요구나 상위 요구에서 실제로 도출된 것이어야 한다 | 출처를 알 수 없는 요구사항 | 상위 요구사항으로의 추적 링크 존재 여부 |
| **일치함 (Correct)** | 실제 이해관계자 니즈를 정확히 반영해야 한다 | 담당자 추측으로 작성된 요구 | 이해관계자 합의/승인 기록 존재 여부 |
| **적합함 (Appropriate, 구현 독립적)** | 필요한 추상화 수준을 지켜야 한다 (요구사항 단계에서 설계를 강제하지 않음) | "MySQL을 사용해 저장한다" (요구사항이 아니라 설계 결정) | "무엇을" 요구하는지와 "어떻게" 구현할지가 섞여 있는지 확인 |
| **준수함 (Conformant)** | 정해진 요구사항 작성 템플릿/스타일을 따라야 한다 | 팀 표준과 다른 형식 | EARS 등 정해진 패턴 사용 여부 |

## 요구사항 집합(명세서) 품질 특성

| 특성 | 의미 | 점검 방법 |
|---|---|---|
| **완전함 (Complete)** | 필요한 모든 요구사항이 포함되어 있고, 미정 사항(TBD)이 없어야 한다 | 이해관계자 요구사항 대비 커버리지 확인, TBD/TBR 항목 잔존 여부 |
| **일관성 (Consistent)** | 요구사항 간 모순이 없어야 한다 (동일 대상에 대해 다른 요구를 하지 않음) | 유사/중복 요구사항 간 수치·조건 비교 |
| **실현 가능함 (Affordable/Feasible)** | 전체 집합이 예산/일정 내에서 구현 가능해야 한다 | 우선순위와 리소스 계획 대조 |
| **이해 가능함 (Comprehensible)** | 이해관계자가 자신의 전문성 수준에서 이해할 수 있어야 한다 | 과도한 전문 용어/약어에 대한 용어집 존재 여부 |
| **검증 가능함 (Validatable)** | 전체 집합이 실제 요구를 반영하는지 이해관계자가 확인할 수 있어야 한다 | 리뷰/승인 이력 존재 여부 |

## 판정 가이드

- 한 요구사항이 여러 특성을 동시에 위반할 수 있습니다. 모든 위반 유형을 나열하되, **검증 불가능함**과 **복합 요구(단일성 위반)** 두 가지가 가장 흔하고 후속 개발(테스트 설계, 추적성)에 가장 큰 영향을 미치므로 우선순위를 높게 두세요.
- "빠르게", "충분히", "적절히", "가능한 한" 같은 부사는 대부분 모호성 위반의 신호입니다. 발견 즉시 정량 기준으로 재작성을 제안하세요.
- 재작성 제안 시 `ears-syntax.md`의 패턴을 사용하면 상당수의 모호성/단일성/완전성 문제가 구조적으로 예방됩니다.
