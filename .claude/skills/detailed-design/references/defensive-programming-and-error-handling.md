# 오류 처리 및 방어적 프로그래밍 (ISO 26262-6 Table 5)

이 참조는 ISO 26262-6에서 공개적으로 알려진 "방어적 프로그래밍을 위한 설계 원칙"을 재구성한 것입니다. 안전 관련 유닛(ASIL이 부여된 기능)에는 예외 없이 적용합니다.

## 방어적 설계 원칙

| 원칙 | 설명 | 상세설계서 반영 위치 |
|---|---|---|
| 입력값 범위/타당성 검사 (Range & plausibility checks) | 함수 진입 시 파라미터가 유효 범위/물리적으로 타당한 값인지 검사 | 5장 함수 계약의 사전조건 + 10장 오류와 방어 동작 |
| 오류 검출 (Error detection) | 계산 결과, 통신 데이터, 저장 데이터의 손상을 checksum/CRC 등으로 검출 | 10장 |
| 오류 처리 (Error handling) | 검출된 오류에 대한 명시적 대응(재시도, 안전 상태 전이, 진단 코드 기록) | 10장, 8장(상태전이)과 연계 |
| 이질적 실행/모니터링 (Diverse execution / control flow monitoring) | 중요 계산의 이중화, 워치독, 제어흐름 모니터링 (ASIL이 높은 기능에 한해 적용, 과도한 적용 지양) | 10장 |
| 자원 사용의 정적 추정 (Static resource estimation) | 스택 깊이, 실행시간의 정적 추정 및 여유 마진 확보 | 13장 구현 경계 또는 별도 자원 분석 |

## 오류 처리 설계 절차 (템플릿 10장)

1. **검출 위치**: 어떤 함수/경계에서 오류를 검출할 것인지 명시합니다 (가능한 한 오류가 발생한 지점에 가까운 곳에서 검출).
2. **전파 차단**: 검출된 오류가 호출자에게 어떻게 전달되는지(반환 코드, 예외, 오류 콜백) 정의하고, 오류가 상위로 그대로 전파되어 시스템 전체에 영향을 주지 않도록 격리 지점을 명시합니다 (아키텍처 수준 "오류 격리"의 유닛 수준 구체화).
3. **기록**: 진단을 위한 로그/오류 코드 기록 방식을 정의합니다.
4. **복구/안전 상태**: 재시도 가능 여부, 안전 상태로의 전이 조건을 정의합니다. 정보가 없으면 TBD로 표시하고 안전 목표 담당자 확인을 요청합니다.
5. **유효하지 않은 입력에 대한 기본 동작**: 사전조건을 만족하지 않는 호출이 들어왔을 때의 명시적 동작(거부/기본값/오류 반환)을 정의합니다 — "일어나지 않는다고 가정"하고 방치하지 않습니다.

## 과도한 방어 코드 지양

방어적 설계는 "검증 가능하고 실제로 발생 가능한 오류"에 대해서만 적용합니다. 발생 불가능한 경로에 대한 방어 코드나, ASIL이 낮은 QM 기능에 안전 등급 기능 수준의 이중화를 요구하는 것은 과도한 설계이므로 제안하지 않습니다.
