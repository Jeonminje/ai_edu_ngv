# 모듈 분해 및 상세설계 원칙 (A-SPICE SWE.3 + ISO 26262-6)

이 참조는 A-SPICE 4.1 SWE.3(소프트웨어 상세설계 및 유닛구현) BP와 ISO 26262-6 Table 4(소프트웨어 유닛 설계·구현 원칙)에서 공개적으로 알려진 원칙을 재구성한 것입니다.

## A-SPICE SWE.3 Base Practice — 설계서에 반드시 반영

| BP | 반드시 반영할 산출물 |
|---|---|
| 유닛 단위 상세설계 | 아키텍처 요소를 구현 단위(함수/클래스/모듈)로 분해 |
| 인터페이스 상세 정의 | 함수 시그니처, 자료형, 반환값까지 구체화된 인터페이스 |
| 동적 동작 상세 기술 | 호출 순서, 알고리즘, 상태전이 상세 |
| 자원 사용 분석 | 스택/힙/실행시간 등 유닛 수준 자원 추정 |
| 유닛 구현 (코딩 표준 준수) | 코딩 규칙 준수 여부, 정적분석 결과 |
| 아키텍처와의 일관성/추적성 확립 | 아키텍처 ↔ 상세설계 ↔ 코드 추적 매트릭스 |

`aspice-auditor` 스킬의 SWE.3 체크리스트로 산출물 자체의 CL2 충족 여부를 별도 감사할 수 있습니다. 이 스킬은 "상세설계를 어떻게 수행할 것인가"에 집중합니다.

## 선행 조건: 아키텍처 설계와의 일관성

상세설계는 반드시 승인된 아키텍처 설계서(`architecture-design` 스킬로 작성된 산출물, `TPL-SWE2-001`)를 입력으로 삼습니다.

- 아키텍처에서 정의된 컴포넌트 경계, 인터페이스 계약(제공자/사용자, 데이터 계약, 사전/사후조건)을 **변경 없이** 세분화해야 합니다. 상세설계 과정에서 아키텍처 수준 인터페이스 계약과 상충하는 내용이 발견되면 임의로 수정하지 말고, 아키텍처 변경 요청(SUPP.10)이 필요함을 사용자에게 알립니다.
- 아키텍처 컴포넌트에 대응하지 않는 구현 단위(고아 유닛)나, 반대로 구현되지 않은 아키텍처 컴포넌트(누락)를 모두 식별해 보고합니다.

## 모듈 분해 절차

1. 아키텍처 요소(컴포넌트) 각각을 구현 단위(함수, 클래스, 모듈, 파일)로 분해합니다.
2. 각 구현 단위에 ID, 책임, 소스 위치(경로/파일명 예정 위치)를 부여합니다.
3. 분해 시 상위 스킬(`architecture-design`)의 응집도/결합도/SOLID 기준을 **유닛 수준에서도 동일하게** 적용합니다 — 하나의 함수/클래스가 여러 이유로 변경되어야 한다면(SRP 위반) 더 세분화합니다.
4. 유닛 간 호출 관계(3장 "상세 호출관계")를 정의할 때도 아키텍처 수준과 동일하게 순환 호출을 금지하고, 호출은 반드시 상세 인터페이스(함수 시그니처)를 통해서만 이루어지도록 합니다.

## ISO 26262-6 Table 4 — 소프트웨어 유닛 설계/구현 원칙

ASIL이 높을수록 아래 원칙 준수를 더 엄격히 요구합니다. 위반이 필요한 경우 반드시 근거와 대체 안전조치를 문서화합니다.

| 원칙 | 설명 |
|---|---|
| 하나의 진입점/하나의 종료점 (One entry, one exit point) | 함수는 원칙적으로 단일 진입/단일 종료를 갖는다 |
| 제한된 크기 (Restricted size of functions) | 함수/유닛 크기를 제한하여 이해 가능성을 확보한다 |
| 낮은 순환 복잡도 (Low complexity) | 분기/조건 복잡도를 제한한다 |
| 강한 자료형 사용 (Strong typing) | 암묵적 형변환을 피하고 명시적 자료형을 사용한다 |
| 제한된 포인터 사용 (Restricted use of pointers) | 포인터 산술, 다중 간접참조를 제한한다 |
| 동적 메모리 할당 제한 | 런타임 동적 할당/해제를 제한하거나 금지한다 (ASIL이 높을수록 강하게 적용) |
| 재귀 사용 제한 | 재귀 호출의 종료 조건과 자원 사용을 명시적으로 분석한다 |
| 무조건 분기(goto) 회피 | 제어 흐름을 명확히 유지한다 |
| 숨은 데이터 흐름 회피 | 전역 변수를 통한 암묵적 데이터 전달을 피한다 (상위 스킬의 "공통 결합 금지"와 동일 원칙) |
| 인터럽트 사용 제한 | 인터럽트 우선순위/재진입성을 명시적으로 분석한다 |

이 표는 템플릿 11장 "코딩 및 검증 규칙"과 6장 "핵심 알고리즘" 작성 시 근거로 사용합니다.
