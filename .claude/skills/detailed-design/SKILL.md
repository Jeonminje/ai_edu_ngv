# 상세설계 스킬

이 스킬은 A-SPICE 4.1 SWE.3(소프트웨어 상세설계 및 유닛구현)과 ISO 26262-6(소프트웨어 개발)에서 공개적으로 알려진 원칙을 결합해, 승인된 아키텍처 설계를 구현 가능한 수준의 모듈/함수/알고리즘 설계로 구체화하는 프레임워크로 재구성해 제공합니다.

**중요**: 아래 내용은 원문 표준의 축약이 아니라 공개적으로 알려진 원칙을 재구성한 실무 참조 자료입니다. 계약/인증 목적의 공식 평가에는 원본 표준 문서를 대조해야 함을 사용자에게 필요 시 안내하세요.

## 이 프로젝트에 적용되는 핵심 제약 (항상 지킬 것, 예외 없음)

1. **아키텍처와의 일관성**: 상세설계는 승인된 아키텍처 설계서(`architecture-design` 스킬 산출물)를 입력으로 하며, 아키텍처 수준 컴포넌트 경계·인터페이스 계약을 임의로 변경하지 않습니다. 상충이 발견되면 아키텍처 변경 요청이 필요함을 알립니다 → `references/module-decomposition.md`
2. **유닛 수준에서도 높은 응집력/낮은 결합도/SOLID 유지**: 함수/클래스로 세분화할 때도 단일 책임과 순환 호출 금지를 그대로 적용합니다 → `references/module-decomposition.md`
3. **함수 계약 필수**: 모든 핵심 함수는 입력/출력/사전조건/사후조건/부작용/예외/시간 제약을 갖춰야 합니다 → `references/function-contracts-and-datatypes.md`
4. **경계값과 결정 로직의 명시적 정의**: 알고리즘의 경계값, 조건 조합별 기대 동작(결정 테이블), 상태전이 상세를 빠짐없이 정의합니다 → `references/algorithm-and-behavior-design.md`
5. **방어적 프로그래밍(ISO 26262-6)**: 입력 검증, 오류 검출/처리/기록/복구를 설계에 포함하되 과도한 방어 코드는 지양합니다 → `references/defensive-programming-and-error-handling.md`
6. **코딩/검증 규칙과 추적성**: 코딩 표준, 정적분석, 단위검증 커버리지 기준을 명시하고, 아키텍처↔상세설계↔소스↔단위시험 양방향 추적을 유지합니다 → `references/coding-and-verification-rules.md`
7. **회사 지정 설계서 양식(TPL-SWE3-001) 준수**: 산출물은 반드시 아래 양식 구조를 따릅니다 → `references/document-template-mapping.md`

## 사용 절차

1. **작업 유형 파악**: (a) 아키텍처 요소 전체의 상세설계 신규 작성, (b) 기존 상세설계 리뷰(계약 완전성/방어적 설계/커버리지 기준 점검), (c) 특정 함수/알고리즘/상태전이만 설계하는 부분 요청 중 어디에 해당하는지 구분합니다.
2. **입력 확인**: 대상 아키텍처 설계서(컴포넌트, 인터페이스 계약)를 Read/Grep으로 실제 확인합니다. 아키텍처 설계서가 없으면 사용자에게 `architecture-designer` 서브에이전트로 먼저 작성할 것을 안내하거나, 최소한 대상 컴포넌트의 인터페이스 정보를 요청합니다.
3. **모듈 분해**: `module-decomposition.md`에 따라 아키텍처 요소를 구현 단위로 분해하고, 아키텍처와의 정합성(고아 유닛/누락 컴포넌트 없음)을 확인합니다.
4. **함수 계약 정의**: `function-contracts-and-datatypes.md`의 9개 항목에 따라 핵심 함수 계약을 빠짐없이 작성합니다.
5. **알고리즘/로직 상세화**: `algorithm-and-behavior-design.md`에 따라 알고리즘, 결정 테이블, 상태전이, (해당 시) API 상세를 작성합니다.
6. **오류 처리 설계**: `defensive-programming-and-error-handling.md`에 따라 오류 검출/처리/기록/복구를 정의합니다.
7. **코딩 규칙/추적성 정의**: `coding-and-verification-rules.md`에 따라 코딩 표준·검증 기준·요구사항 할당·구현 경계·추적성을 정의합니다.
8. **양식에 맞춰 산출물 작성**: `document-template-mapping.md`의 섹션 매핑에 따라 Markdown 초안을 작성하고, 실제 `.docx`/`.drawio` 반영 절차를 사용자에게 안내합니다.
9. **자체 점검**: 결과 제출 전 아래 "완료 조건"을 모두 확인합니다.

- [ ] 모듈 분해가 아키텍처 수준 인터페이스 계약과 상충하지 않는가?

- [ ] 모든 핵심 함수가 입력/출력/사전조건/사후조건/부작용/예외/시간 제약을 갖추는가?
