# 품질 지표 (CLAUDE.md 구현 지침 — 예외 없이 준수)

이 프로젝트의 모든 구현 코드는 아래 품질 지표를 **반드시** 준수해야 합니다. Refactor 단계마다 측정하고, 기준을 넘으면 병합/완료로 보고하지 않습니다.

| 지표 | 기준 | 초과 시 조치 |
|---|---|---|
| 함수 순수 코드 라인수 | 50라인 이하 (주석/공백 제외 실행 코드 기준) | 책임을 분리해 하위 함수로 추출 (SRP 적용) |
| 함수 순환 복잡도 (Cyclomatic Complexity) | 10 이하 | 조건 분기를 정책 의사결정표 기반 함수로 분리하거나 조기 반환(guard clause)으로 단순화 |
| 중복 코드 | 최대 7라인까지 허용, 8라인 이상 중복은 불허 | 공통 함수/헬퍼로 추출 |
| 주석 비율 | Doxygen 방식 주석을 전체 코드의 20% 이상 작성 | 함수/모듈 단위 Doxygen 주석 보강 (`naming-and-comment-style.md` 참조) |
| 네이밍 | 함수명, 변수명은 camelCase 사용 | PEP 8의 snake_case보다 이 프로젝트 규칙(camelCase)을 우선 |
| Branch(분기) 커버리지 | 단위 테스트에서 **100%** 달성 | 실행되지 않은 분기가 있으면 그 분기를 실행하는 테스트 케이스(긍정/부정)를 추가 |
| 테스트 성공률 | 전체 단위 테스트의 **100%** Pass | 실패한 테스트가 있으면 코드를 고치거나(버그) 테스트를 고쳐서(잘못된 기대값) 100%로 만든 뒤에만 완료 보고 |

## 측정 방법 (오픈소스 도구 사용 — CLAUDE.md 필수 지침)

CLAUDE.md는 "순환 복잡도, 함수라인수 등 측정 지표는 오픈소스 도구를 이용한다"를 명시합니다. 임의로 육안 판단만으로 통과 여부를 결정하지 말고 아래와 같은 도구로 실측하고 결과를 근거로 제시합니다.

| 지표 | 권장 오픈소스 도구 | 실행 예시 |
|---|---|---|
| 순환 복잡도 | `radon cc` | `radon cc -s <파일/디렉터리>` |
| 함수 라인수 / 원시 지표 | `radon raw` 또는 `radon cc`의 결과와 함께 직접 카운트 | `radon raw <파일>` |
| 중복 코드 | `pylint`의 `duplicate-code` 검사기 | `pylint --disable=all --enable=duplicate-code <디렉터리>` |
| 코딩 스타일/네이밍 위반 탐지 | `pylint` 또는 `flake8` (camelCase 규칙은 프로젝트 설정으로 커스터마이즈 필요 — 기본 PEP8 규칙과 충돌 시 프로젝트 규칙 우선) | `pylint <파일>` |
| Doxygen 주석 형식 검증 | `doxygen` (Python 입력 필터로 `doxypypy` 병용 권장) | `doxygen Doxyfile` |
| Branch 커버리지 / 테스트 성공률 | `coverage.py` (`unittest` 실행을 감싸서 측정) | `coverage run --branch -m unittest discover` → `coverage report -m` |

선택한 도구가 프로젝트에 아직 설치되어 있지 않으면, 임의로 다른 방식(육안 검토만)으로 대체 보고하지 말고 사용자에게 설치 여부를 확인하거나 설치를 제안합니다. 측정 결과 수치를 제시하지 않고 "기준을 만족한다"고만 보고하지 마세요.

## 예외 처리

- 위 지표를 예외적으로 초과해야 하는 불가피한 사유(예: 자동 생성 코드, 외부 라이브러리 래퍼)가 있다면 임의로 통과 처리하지 말고, 사유와 함께 사용자에게 예외 승인을 요청합니다.
