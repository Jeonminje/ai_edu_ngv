# 알고리즘, 정책 결정, 상태전이 상세 설계

## 핵심 알고리즘 (템플릿 6장)

- 처리 순서, 판단 조건, 경계값, 계산 근거를 의사코드 또는 흐름도로 작성합니다.
- 경계값(최소/최대/0/음수/오버플로 가능 지점)을 명시적으로 나열하고, 각 경계값에서의 기대 동작을 함께 기술합니다 — 경계값 누락은 이후 SWE.4 단위시험에서 커버리지 갭으로 이어집니다.
- 순환 복잡도가 높아지는 지점(중첩 분기 3단 이상)은 별도 함수로 분리할지 검토합니다 (module-decomposition.md의 "낮은 순환 복잡도" 원칙).

## 정책 의사결정표 (템플릿 7장)

여러 입력 조건의 조합에 따라 동작이 달라지는 로직은 자연어 서술 대신 결정 테이블로 정의합니다.

```
| 조건1 | 조건2 | 조건3 | → 기대 동작 | 우선순위/충돌 해결 규칙 |
|---|---|---|---|---|
| T | T | - | ... | ... |
| T | F | T | ... | ... |
```

- 조건 조합이 상충하는 경우(예: 두 규칙이 동시에 만족되지만 다른 동작을 요구) 우선순위 또는 명시적 충돌 해결 규칙을 반드시 정의합니다. 정의되지 않은 조합(don't-care가 아닌 실제 누락)은 갭으로 보고합니다.

## 상태전이 상세 (템플릿 8장)

아키텍처 수준 상태전이(개략)를 유닛 구현 수준으로 구체화합니다.

- 상태를 저장하는 위치(어떤 변수/자료구조), 전이를 수행하는 함수, 전이를 유발하는 이벤트, 전이 조건(가드), 타이머 기반 전이, 초기화 시 진입 상태를 명시합니다.
- 금지된 전이(정의되지 않은 이벤트가 특정 상태에서 발생했을 때의 동작)를 명시적으로 정의합니다 — 방어적 설계 원칙(`defensive-programming.md`)과 연계합니다.

## Web 및 API 상세 (템플릿 9장, 해당 시)

- 엔드포인트, 요청/응답 스키마, 입력 검증 규칙, 오류 코드 체계, 세션/인증 경계, 보안 경계(권한 검사 위치)를 정의합니다.
- 이 항목은 아키텍처 수준 "외부 인터페이스" 명세를 실제 API 계약으로 구체화한 것입니다 — 아키텍처 문서의 외부 인터페이스 항목과 일치하는지 확인합니다.
