# SUPP 프로세스 (지원 프로세스)

## SUPP.1 품질보증 (Quality Assurance)

**목적**: 프로젝트 산출물과 프로세스가 정의된 요구사항/계획에 부합하는지 독립적으로 보증한다.

**BP**:
- 품질보증 전략/계획 수립 (독립성 확보 포함)
- 제품/프로세스 품질보증 활동 수행
- 부적합 사항 식별 및 기록
- 부적합 사항의 해결 확인
- 관련자에게 품질보증 결과 보고

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 품질보증 계획 | QA 담당자의 독립성(개발조직과 분리) 명시, 점검 대상/주기 정의 |
| QA 점검 기록 | 점검 일자, 대상, 발견 사항, 심각도 |
| 부적합 조치 이력 | 부적합 사항의 종료(closure) 확인 근거 |

## SUPP.2 검증 (Verification)

**목적**: 산출물이 정의된 요구사항을 만족하는지 검증한다 (일반 검증 프로세스; 각 엔지니어링 프로세스의 구체 검증과 별개로 조직 차원의 검증 전략을 다룸).

**BP**:
- 검증 전략 수립 (대상, 방법, 기준)
- 검증 기준 정의
- 검증 수행
- 결과 기록 및 결함 관리 연계

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 검증 전략/계획 | 검증 대상 산출물 목록과 각각의 검증 방법(리뷰/테스트/분석) 명시 |
| 검증 결과 기록 | 기준 대비 Pass/Fail, 발견된 결함과 SUPP.9(문제해결)와의 연계 |

## SUPP.4 공동검토 (Joint Review)

**목적**: 프로젝트 상태와 산출물을 이해관계자(고객 포함)와 공동으로 검토하여 합의된 진행을 보장한다.

**BP**:
- 공동검토 전략 수립 (검토 유형: 프로젝트관리 검토 / 기술 검토)
- 검토 대상/기준 준비
- 검토 수행 및 참석자 확인
- 검토 결과(이슈, 액션아이템) 기록
- 액션아이템 추적 및 종료 확인

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 검토 계획 | 검토 유형별 주기, 참석 대상 정의 |
| 검토 기록/회의록 | 일시, 참석자, 논의사항, 액션아이템, 담당자, 기한 |
| 액션아이템 추적 목록 | 상태(Open/Closed)와 종료 근거 |

## SUPP.7 문서화 (Documentation)

**목적**: 프로젝트에서 생성되는 문서가 정의된 표준에 따라 관리되도록 한다.

**BP**:
- 문서화 전략 수립 (문서 목록, 표준/템플릿)
- 문서 식별 규칙 정의
- 문서 검토 및 승인
- 문서 배포 및 접근성 확보
- 문서 유지보수 (개정 이력 관리)

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 문서화 전략/표준 | 문서 종류별 템플릿, 명명규칙, 승인 절차 정의 |
| 문서 목록/레지스트리 | 모든 산출물 문서의 현재 버전과 위치 추적 가능 |

## SUPP.8 형상관리 (Configuration Management)

**목적**: 산출물(형상항목)의 무결성을 유지하고 변경을 통제된 방식으로 관리한다.

**BP**:
- 형상관리 전략 수립
- 형상항목 식별
- 형상관리 시스템 구축 (저장소, 접근통제)
- 베이스라인 수립
- 변경 통제 (변경 이력 추적)
- 형상 상태 보고
- 형상 감사 수행

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---| 
| 형상관리 계획 | 형상항목 식별 규칙, 베이스라인 시점, 저장소/도구 명시 |
| 형상항목 목록 | 산출물별 버전/베이스라인 이력이 실제로 확인 가능(예: git tag, 릴리즈 태그) |
| 형상 상태 보고 | 특정 시점의 형상 상태를 재구성할 수 있는 근거 |

**참고**: 이 프로세스는 감사 시 가장 실증하기 쉬운 프로세스입니다 — 버전관리 시스템(git 등)의 커밋/태그/브랜치 이력을 직접 확인해 GP 2.2.5(추적성/형상관리)의 증거로 함께 활용하세요.

## SUPP.9 문제해결관리 (Problem Resolution Management)

**목적**: 식별된 문제(결함 등)가 식별·분석·해결되고 재발이 방지되도록 관리한다.

**BP**:
- 문제 기록 (고유 ID, 상태)
- 문제 분석 (근본원인 등)
- 문제 우선순위/영향 평가
- 문제 해결 조치
- 해결 확인 및 종료
- 문제 상태 추적 및 보고

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 문제(결함) 기록 시스템 | 각 항목에 ID, 상태(Open/In Progress/Closed), 우선순위, 담당자 |
| 근본원인 분석 기록 (해당 시) | 재발방지 조치 연결 |
| 문제 상태 보고 | 오픈 이슈 추이 등 추적 가능 |

## SUPP.10 변경요청관리 (Change Request Management)

**목적**: 산출물에 대한 변경 요청이 식별·분석·승인·추적되도록 관리한다.

**BP**:
- 변경요청 기록 (고유 ID)
- 변경 영향 분석
- 변경요청 검토 및 승인/거부 결정
- 승인된 변경 구현 추적
- 변경 상태 보고
- 관련 이해관계자에게 결정 통지

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 변경요청 기록 시스템 | ID, 상태, 영향분석 결과, 승인자/승인일 |
| 영향분석 기록 | 변경이 요구사항/설계/일정/자원에 미치는 영향 |
| 변경 이력 | 승인된 변경이 실제 형상항목(SUPP.8)에 반영된 증거 |
