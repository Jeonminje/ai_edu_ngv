# SWE 프로세스 (소프트웨어 엔지니어링)

## SWE.1 소프트웨어 요구사항 분석 (Software Requirements Analysis)

**목적**: 시스템 요구사항/아키텍처로부터 소프트웨어 요구사항을 도출하고 분석한다.

**BP**:
- 소프트웨어 요구사항 명세 (기능/비기능 포함)
- 요구사항 구조화/분류
- 상호 영향 분석
- 검증 기준 정의
- 시스템 요구사항과의 일관성 확보
- 양방향 추적성 확립 (시스템↔SW 요구사항)
- 요구사항 커뮤니케이션

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| SW 요구사항 명세 | 각 요구사항에 ID, 우선순위, 검증기준 포함 |
| 추적성 매트릭스 (시스템요구사항↔SW요구사항) | 양방향 링크 존재, 커버리지 갭 식별 |
| 영향/일관성 분석 기록 | 요구사항 변경 시 영향받는 항목 목록 |

## SWE.2 소프트웨어 아키텍처 설계 (Software Architectural Design)

**목적**: SW 요구사항을 만족하는 소프트웨어 아키텍처를 설계한다.

**BP**:
- 아키텍처 설계 (SW 구성요소, 인터페이스)
- 요구사항의 아키텍처 요소 배분
- 인터페이스 정의
- 동적 동작 기술
- 자원 사용(메모리/타이밍 등) 고려
- 대안 평가
- 일관성/추적성 확립 (SW요구사항↔아키텍처)

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| SW 아키텍처 설계서 | 구성요소, 인터페이스, 데이터흐름, 동적 시나리오(시퀀스/상태 다이어그램 등) 포함 |
| 자원 사용 분석 | 메모리/CPU/타이밍 제약에 대한 근거 |
| 추적성 매트릭스 (SW요구사항↔아키텍처) | 배분 누락 없음 |

## SWE.3 소프트웨어 상세설계 및 유닛구현 (Software Detailed Design and Unit Construction)

**목적**: 소프트웨어 유닛을 상세 설계하고 구현한다.

**BP**:
- 유닛 단위 상세설계
- 인터페이스 상세 정의
- 동적 동작 상세 기술
- 자원 사용 분석
- 유닛 구현 (코딩 표준 준수)
- 아키텍처와의 일관성/추적성 확립 (아키텍처↔상세설계↔코드)

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| SW 상세설계서 | 유닛별 알고리즘/자료구조/인터페이스가 아키텍처와 정합 |
| 소스 코드 | 코딩 표준(정적분석 규칙 등) 준수 여부 확인 가능 |
| 추적성 매트릭스 (아키텍처↔상세설계↔코드) | 코드 모듈이 설계 요소와 매핑됨 |

## SWE.4 소프트웨어 유닛검증 (Software Unit Verification)

**목적**: 소프트웨어 유닛이 상세설계와 일치하고 결함이 없음을 검증한다.

**BP**:
- 유닛 검증 기준 정의 (커버리지 목표 등)
- 유닛 테스트 케이스 설계 (상세설계 기반)
- 유닛 검증 수행 (테스트 및/또는 정적분석)
- 결과 기록
- 양방향 추적성 (상세설계↔유닛테스트)

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| 유닛 테스트 명세 | 각 유닛/함수에 대한 테스트 케이스, 커버리지 기준(예: MC/DC, 분기 커버리지) 명시 |
| 유닛 테스트 결과 | Pass/Fail, 커버리지 수치, 결함 연결 |
| 정적분석 결과 (해당 시) | 규칙 위반 목록 및 처리 상태 |

## SWE.5 소프트웨어 통합 및 통합시험 (Software Integration and Integration Test)

**목적**: 소프트웨어 유닛/구성요소를 통합하고 아키텍처 설계를 만족하는지 검증한다.

**BP**:
- 통합 전략 수립
- 통합 검증 기준 정의
- 통합 테스트 케이스 설계 (아키텍처 기반)
- 통합 수행 및 결과 기록
- 회귀 전략
- 양방향 추적성 (아키텍처↔통합테스트)

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| SW 통합 전략/계획 | 통합 순서, 스텁/드라이버 필요 여부 명시 |
| 통합 테스트 명세 및 결과 | 인터페이스별 테스트 케이스와 실행 결과 |
| 추적성 매트릭스 (아키텍처↔통합테스트) | 인터페이스 커버리지 확인 가능 |

## SWE.6 소프트웨어 자격시험 (Software Qualification Test)

**목적**: 통합된 소프트웨어가 SW 요구사항을 만족하는지 검증한다.

**BP**:
- 자격시험 전략/기준 수립
- SW 요구사항 기반 테스트 케이스 설계
- 시험 환경 정의
- 시험 수행 및 결과 기록
- 양방향 추적성 (SW요구사항↔자격시험)

**기대 산출물**:
| 산출물 | 내용 지표 |
|---|---|
| SW 자격시험 명세 | 각 SW 요구사항에 최소 1개 테스트 케이스 매핑 |
| 시험 결과 보고서 | Pass/Fail, 결함 연결, 재시험 이력 |
| 추적성 매트릭스 (SW요구사항↔자격시험) | 커버리지 갭 명시 |
