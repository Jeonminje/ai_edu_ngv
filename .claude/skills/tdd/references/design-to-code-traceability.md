# 설계-코드 일관성 및 추적성

구현 단계는 개발 생명주기(분석→설계→구현→테스트)의 마지막 이전 단계이며, 임의로 설계를 벗어난 구현을 하지 않습니다.

## 입력 확인

- 대상 함수/모듈의 상세설계서(`TPL-SWE3-001`)에서 함수 계약, 알고리즘, 결정 테이블, 상태전이, 오류 처리 정의를 Read/Grep으로 실제 확인합니다.
- 상세설계서가 없거나 대상 범위가 설계서에 없으면, 구현을 진행하지 말고 `detailed-designer` 서브에이전트로 먼저 상세설계를 작성하도록 사용자에게 안내합니다.

## 구현 중 설계와 다른 점을 발견한 경우

- 상세설계서의 계약을 그대로 구현할 수 없는 기술적 제약을 발견하면(예: 언어/라이브러리 제약), 임의로 계약을 바꿔 구현하지 말고 사용자에게 알리고 상세설계서 갱신 여부를 확인합니다.
- 구현이 끝난 뒤 계약과 실제 동작이 다르면 "완료"로 보고하지 않습니다.

## 추적성 산출물

- 구현 완료 시 소스 파일/함수와 상세설계 유닛 ID, SW 요구사항 ID의 매핑을 갱신하거나, 상세설계서의 추적성(14장) 표를 갱신하도록 사용자에게 안내합니다.
- 테스트 코드는 이후 `SWE.4` 단위시험(`TPL-SWE4-001`/`TPL-SWE4-002`) 산출물과 연계될 수 있음을 안내합니다 — 이 스킬은 TDD로 작성된 테스트가 곧 단위시험의 기초 자료가 됨을 전제로 하되, 정식 단위시험 명세/결과 산출물 작성은 별도 요청 시 다룹니다.
