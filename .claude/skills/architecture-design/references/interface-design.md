# 인터페이스 설계 및 인터페이스 전용 통신 규칙

이 프로젝트에서는 **컴포넌트 간 통신은 반드시 인터페이스를 통해서만** 이루어져야 합니다. 이는 A-SPICE SWE.2 BP("인터페이스 정의")와 ISO 26262-6 캡슐화 원칙, DIP(의존성 역전)를 실현하는 핵심 규칙입니다.

## 필수 규칙

1. **인터페이스 우선 설계**: 컴포넌트의 내부 구현을 설계하기 전에 그 컴포넌트가 제공/요구하는 인터페이스부터 정의합니다.
2. **직접 참조 금지**: 어떤 컴포넌트도 다른 컴포넌트의 내부 필드, 내부 클래스, private 구현 세부사항을 직접 참조하거나 수정할 수 없습니다. 모든 상호작용은 명시적으로 정의된 인터페이스(제공 인터페이스 Provided Interface / 요구 인터페이스 Required Interface) 호출로만 이루어집니다.
3. **공유 가변 상태 금지**: 두 개 이상의 컴포넌트가 전역/공유 메모리를 직접 읽고 쓰는 설계는 허용하지 않습니다. 상태 공유가 필요하면 상태를 소유하는 별도 컴포넌트를 정의하고, 그 컴포넌트의 인터페이스를 통해서만 접근합니다.
4. **인터페이스 없는 컴포넌트 금지**: 아키텍처 다이어그램에 등장하는 모든 컴포넌트는 최소 하나 이상의 제공 인터페이스를 가져야 합니다 (외부에서 전혀 호출되지 않는 컴포넌트는 존재 이유를 재검토).

## 인터페이스 명세 필수 항목 (템플릿 6장)

각 인터페이스는 아래 항목을 빠짐없이 정의합니다. 항목이 확인되지 않았으면 TBD로 표시하고 사용자에게 확인을 요청하며, 임의로 채우지 않습니다.

| 항목 | 설명 |
|---|---|
| 인터페이스 ID | 고유 식별자 (예: IF-COMP01-01) |
| 제공자 (Provider) | 이 인터페이스를 구현/제공하는 컴포넌트 |
| 사용자 (Consumer) | 이 인터페이스를 호출하는 컴포넌트(들) |
| 오퍼레이션/시그니처 | 메서드명, 파라미터, 반환값 (또는 이벤트명, 메시지 스키마) |
| 데이터 계약 | 입출력 데이터 구조, 단위, 유효 범위 |
| 사전조건 / 사후조건 | 호출 전 만족해야 할 상태, 호출 후 보장되는 상태 |
| 호출 조건 / 동기·비동기 여부 | 호출 시점, 동시성 제약 |
| 시간 제약 | 응답시간, 주기, 타임아웃 (해당 시 — 특히 안전/실시간 관련 인터페이스) |
| 오류 계약 | 실패 시 반환값/예외/오류 코드와 호출자의 대응 책임 |

내부 인터페이스(6.1)와 외부 인터페이스(6.2)는 템플릿 구조에 따라 구분합니다. 외부 인터페이스(하드웨어, 통신, 외부 서비스)는 변경 가능성이 상대적으로 높으므로, 이를 별도 어댑터 컴포넌트 뒤로 격리해 내부 컴포넌트가 외부 인터페이스 변경에 직접 노출되지 않게 하는 것을 기본 원칙으로 제안합니다.

## LSP/ISP와의 연계

- 하나의 인터페이스를 여러 컴포넌트가 서로 다른 목적으로 사용한다면, 클라이언트별로 필요한 오퍼레이션만 묶은 별도 인터페이스로 분리할 것을 제안합니다 (ISP).
- 동일 인터페이스에 대한 복수 구현체가 존재할 경우, 사전조건을 강화하거나 사후조건을 약화하는 구현체가 없는지 점검합니다 (LSP 위반 시 치환 불가).
